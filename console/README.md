# 轻跳公测运营后台

状态：本地可运行，未部署公网。账号登录、应用权益校验和支付尚未实现。

## 在这台 Windows 电脑使用

1. 双击 `console/启动后台.cmd`，后台独立运行并打开管理页；检测到服务已运行时会复用，不重复占用端口。使用现有 Node 24 运行时，没有则从 PATH 找 `node`。
2. 浏览器打开 <http://127.0.0.1:3887/admin>。
3. 初次启动自动生成独立管理员密码，保存在 `console/data/首次登录说明.txt`，不会打印到终端或聊天。
4. 下载页为 <http://127.0.0.1:3887/>；反馈页为 <http://127.0.0.1:3887/feedback>。
5. 需要停止时双击 `console/停止后台.cmd`；它会检查 PID、进程名称、命令行与端口归属，只停止本机轻跳服务。之后启动同一个目录，SQLite 数据保留，会话需要重新登录。后台不会被配置成系统开机自启。

当前实例如已运行，直接打开后台，不要重复启动占用同一端口。127.0.0.1 只在这台电脑可访问，不是可以发给公测用户的公网网址；电脑关机后服务也会停止。

其他机器安装 Node 24 后：

```sh
cd console
node setup.mjs
node server.mjs
```

没有 npm 依赖。使用 Node 自带 HTTP、Crypto 和 SQLite；后端测试命令：`node --test --test-timeout=20000 test/console.test.mjs`。

## 反馈闭环

- 下载页 → 网页反馈 → 用户确认提交 → 后台待处理 → 处理中 / 已修复 / 已关闭。
- 默认不附带诊断；设备、系统和联系方式可选，不读取手机无障碍内容。
- 用户拿到反馈编号和删除码后可自行删除。后台只保存删除码哈希，不公开反馈。
- 管理员可以按关键词、状态、问题类型筛选，按 10/20/50/100 条分页，保存备注和导出当前筛选的前 5000 条 CSV（与当前页无关）；对表格公式前缀做了处理。
- 编辑中的备注保存在当前浏览器内存草稿，切换导航、筛选和自动刷新不会覆盖输入；未保存关闭会提示。保存期间锁定该条输入，记录版本冲突返回 409 并保留草稿，需要主动核对和放弃旧修改才能重新读取。关闭标签页或退出后草稿不保留。

当前 APK 自身仍无网络权限。网页反馈通过浏览器提交。已有 APK 的 GitHub Issue 和系统分享不会自动导入本后台；需要用户改用部署后的网页反馈入口。

## 公测规则

当前免费公测。正式收费后，包括公测用户在内的全部用户都需要登录并购买使用权益，不赠送永久资格。计划价 9.9 元，未开放收款。

后台可以发布公告、计划日期和切换“免费公测 / 已发布收费预告”。设置真正 `paid` 阶段会返回 409：没有支付与权益实现时，不提供虚假的收费开关。

旧离线 APK 无法远程撤销。若要求公测期结束后停止免费，正式扩大推广前需要另行完成联网公测凭证、到期校验、账号和服务端权益。当前网页公告和 APK 弹窗只是告知，不是授权系统。

## 部署方案：一个 HTTPS 域名 + 单实例服务 + 持久磁盘

不需要现在买数据库集群。先使用可运行 Node 24 常驻进程的 Linux 主机，Node + SQLite 单实例、Caddy 反向代理。这里没有采购主机、域名或进行公网部署，也没有压测容量承诺。

1. 准备自己的域名，DNS 指向主机；上传仓库代码到 `/opt/qingtiao/`。
2. 创建专用低权限用户 `qingtiao` 和持久目录 `/var/lib/qingtiao`，目录仅该用户可写；安装 Node 24。
3. 使用 `node setup.mjs` 生成新的生产管理员密码哈希。将哈希而非密码写入私有 `/etc/qingtiao-console.env`，参考 `deploy/production.env.example`；配置真实 `PUBLIC_ORIGIN=https://你的域名`，不要带尾斜线。
4. 用 `deploy/qingtiao-console.service` 作为 systemd 服务模板。核对 Node 实际路径，数据目录、用户、代码目录和配置文件权限；配置文件只让服务和管理员读取。
5. 修改 `deploy/Caddyfile` 的示例域名，代理到 `127.0.0.1:3887`。只公开 HTTPS/HTTP 所需端口，不把 Node 端口或数据库目录暴露到公网。Caddy 会在满足域名、DNS 和端口条件时管理 HTTPS 证书；见 [Caddy 官方说明](https://caddyserver.com/docs/automatic-https)。
6. 登录后台检查真实下载与反馈；用自己的手机网络验证下载与反馈链路。检查站点运营者联系方式和隐私页是否符合实际部署情况。
7. 打包带网页反馈入口的 APK：`powershell -ExecutionPolicy Bypass -File .\build.ps1 -PublicSite https://你的域名`。仅接受纯 HTTPS origin；浏览器打开反馈，APK 不直接上传。
8. 小红书使用 `https://你的域名/?channel=xhs`，其他渠道换不同代号。当前固定下载地址是本仓库 GitHub Release；上线前用目标网络验证可达性，国内用户访问不稳定时再实现可信文件托管和完成下载口径，不把跳转冒充完成下载。

`TRUST_PROXY=1` 仅用于当前回环 Caddy 代理方案；代码只在请求来自回环地址时采用代理地址。不要直接信任公网任意请求的 `X-Forwarded-For`，不要把该配置照搬到未经验证的多层代理拓扑。

正式上线前应轮换管理员密码、启用 HTTPS、验证频率限制、保持私有配置和数据库备份、确认磁盘容量，并实际检查公网请求不能直接读取管理接口。模板已提供，但本轮没有在真实云主机上执行这些步骤。

## 数据、备份和恢复

- `data/console.sqlite`：反馈、入口记录、公告和 GitHub 公开计数缓存。
- `data/feedback-deletions.jsonl`：仅随机反馈编号和删除时间，用于恢复备份时重放用户删除，不含反馈正文或联系方式。
- `.env.local`：私有管理员密码哈希、可选 GitHub 读取令牌、站点配置。
- `data/首次登录说明.txt`：初始密码明文。迁移到自己的密码管理器后可自行删除该说明，勿提交。
- `.env.local`、`data/`、`backups/`、日志都已加入 Git 忽略。不要把数据库放进 `public/`。

执行 `node backup.mjs` 使用 SQLite 一致性备份，输出到私有 `backups/`；不直接复制运行中的单个 SQLite 文件，也不把 WAL 忽略。此命令不会自动上传备份。部署后安排每日备份，只保留 7 天，并将删除记录另行备份。

恢复时停止服务，保留最新版 `feedback-deletions.jsonl`，恢复数据库，再启动服务。启动会重放删除记录，请勿用旧删除记录覆盖新记录。到期原始反馈（90 天）、入口记录（365 天）、审计记录（180 天）会在后续请求时清理。删除记录作为防恢复元数据单独保留；不要恢复未经核对的过旧备份。

会话只在内存中，最长 12 小时，退出或服务重启后失效。限流键短暂在内存中，不把 IP、User-Agent 或设备标识写入数据库；代理和云主机日志另行管理。单实例 SQLite 不支持把多个副本指向各自磁盘后期待数据自动合并。

## 0.2.0 工作台更新

导航分为运营概览、反馈工单、推广渠道、公测设置。反馈支持搜索、分页、问题类型、草稿状态和并发修改保护；设置自动刷新不会覆盖编辑。推广页可生成渠道链接并提示本机地址不能对外分享。网页反馈在发送前显示完整预览，支持返回修改和 Escape 关闭；只有确认发送才发起请求。

升级前先执行 `node backup.mjs`。启动时自动给旧反馈表补充 revision 列，不清空旧记录；前端后端应成套更新，旧管理页面需要刷新后再保存。不存在迁移到新数据库后重新填数据的步骤。

可选浏览器验收：安装 Playwright 与 Chrome，设置 `PLAYWRIGHT_MODULE` 和 `CHROME_PATH` 后运行 `node test/browser-smoke.cjs`。它只使用 3888 端口与内存数据库，夹具数据不是正式下载量或真实反馈。生产后台截图单独从 3887 实例抓取。

## 0.2.1 诊断字段修复

用户填入诊断后取消勾选时，浏览器在发送前删除诊断字段；原有服务端丢弃未同意诊断的保护继续保留。隔离浏览器测试检查实际请求 JSON，确认不包含该字段和测试诊断文字。0.2.0 后台包由 0.2.1 替代，APK 仍为 beta.7，不涉及 APK 签名或识别规则改动。

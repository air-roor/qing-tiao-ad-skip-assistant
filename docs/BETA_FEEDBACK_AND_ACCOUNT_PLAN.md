# 轻跳免费公测、运营后台与正式收费方案

更新日期：2026-10-25（Asia/Shanghai）

## 已确定的产品规则

以本次用户决定为准，替换早期“有效反馈用户获得免费兑换码或永久权益”的建议：

> 当前免费公测，用于收集兼容性反馈。正式收费后，所有用户（包括参加过免费公测的用户）均需登录轻跳账号并购买使用权益。公测不赠送永久免费权益。收费日期和最终价格提前公告，当前不接受付款。

沿用此前 9.9 元一次性永久使用的产品设想，当前只作为计划价格，尚未创建商品或开通收款。免费测试不是购买记录，不自动生成付费权益，也不承诺公测用户特殊免费资格。

## 第一阶段：免费公测

1. 准备一个 HTTPS 域名和可常驻运行 Node 24 的服务，部署 `console/`，数据目录使用持久磁盘。
2. 公布下载页和网页反馈入口；小红书等渠道分享自己的 `/?channel=xhs`，用户点击下载后记录入口渠道。
3. 用 `build.ps1 -PublicSite https://你的域名` 打包 APK。它会显示网页反馈入口；APK 本身仍不申请网络权限，上传由浏览器在用户确认后完成。
4. 在后台按待处理、处理中、已修复、已关闭整理反馈，记录复现与修复版本；不要把模拟测试计入真实兼容率。
5. 在新增公开分发前，决定是否需要“公测结束后必须付费才能继续”的技术约束。如果需要，先完成下一阶段的联网授权包，不能只靠收费文案。

## 关键限制：旧离线 APK 不能远程转成收费版

当前已经公开的 beta.5 及更早版本，以及本次没有配置在线权益的 beta.6，均为离线识别包。没有账号、联网授权或到期校验，无法远程强制失效；删除 GitHub 链接也不能撤回用户已经保存的安装包。

因此，“所有人都收费”的可执行定义是：正式版的所有账号都必须购买，包括早期公测用户；没有可验证订单的账号不能获得正式版权益。但不能保证所有人都放弃旧离线包。即使新包增加联网校验，也不能保证不可修改或被破解。

如果必须尽量统一公测结束后的使用条件，首轮大规模推广应使用新的联网公测包，而不是继续扩大旧离线包分发。

## 第二阶段：联网公测与账号灰度（尚未实现）

- 新包首次使用登录账号，但在公测状态下免费发放短期公测凭证；不自动发放永久权益。
- 后台统一维护 `beta / announced / paid` 阶段和真实服务器时间。
- 客户端使用服务端签发、可校验的短期凭证，校验账号、产品、到期时间、设备绑定和签名；不要依靠本地 `isPaid=true` 或修改手机时间。
- 公测凭证的过期时间不得晚于已公告的公测结束时间。公测结束后不再续发免费凭证；离线宽限期必须对用户公开。
- 无有效凭证时，无障碍服务直接返回，不扫描其他应用。用户仍可关闭服务、查看说明、提交反馈、管理账号或删除账号；不要在第三方 App 页面弹付费墙。
- 把登录、退出、设备管理、账号删除、网络故障提示与安全停止功能做完后，再进行免费灰度测试。
- 加入联网能力前更新 APK 的权限和隐私说明，明确后台数据和用途；不上传控件节点、页面正文、IMEI、广告标识或全部应用清单。

## 第三阶段：正式收费（尚未实现）

1. 确定商品、价格、权益范围和支付渠道，准备可用的商户配置。
2. 用户登录后下单，服务端向支付渠道验证订单；客户端支付成功页面不能直接授予永久权益。
3. 同一订单只能授予一次权益；处理重复回调、退款、撤销、恢复购买和换机。
4. 正式收费时，新用户和原公测用户使用同一规则：没有有效付费权益就不能启用正式版自动跳过。
5. 发布清楚的正式版公告和旧版兼容说明，提前说明收费时间，不虚构倒计时，不暗中改变已经售出的永久权益。

需要的核心表：`users`、`login_identities`、`devices`、`orders`、`payment_callbacks`、`entitlements`、`trial_leases`、`account_deletion_requests`。当前运营后台只实现下载、反馈和公告，不冒充完整账号支付系统。

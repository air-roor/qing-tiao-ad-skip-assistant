# 轻跳免费公测、反馈、账号与永久权益方案

更新日期：2026-10-24

## 对用户的公开承诺

轻跳目前处于免费公测阶段，不要求注册账号。推广文案统一写明：

> 轻跳目前免费公测，用于收集不同手机和应用的兼容反馈。公测版本不会突然要求登录；正式账号版和收费规则上线前会提前公告，并为参与有效反馈的早期用户提供迁移或优惠方案。

不要使用“永久免费”“覆盖所有应用”“100% 秒跳”等不可持续或无法验证的承诺。若计划在正式版收费，应从第一次推广起就写“免费公测”，避免用户把测试期免费理解为永久承诺。

## 第一阶段：免费公测

### 应用内反馈闭环

0.3.0-beta.2 已实现本机结构化反馈：

1. 用户选择问题类型；
2. 填写相关应用和可复现描述；
3. 选择是否附带隐私化诊断；
4. 预览并编辑完整内容；
5. 复制、通过系统分享发送，或打开预填的 GitHub Issue；
6. 每份反馈带独立编号，方便在小红书私信、GitHub 和后续回复中对齐。

这一阶段继续保持无网络权限。优点是隐私边界清楚、上线快；限制是无法自动汇总发送结果，用户使用 GitHub 还需要 GitHub 账号。小红书推广时应在置顶评论说明接收渠道，例如“在轻跳内生成反馈，复制后私信发送”，再按反馈编号建立表格。

建议反馈台账至少包含：反馈编号、日期、手机型号、系统版本、目标应用、问题类型、轻跳版本、是否复现、处理状态、修复版本。不要把密码、验证码、聊天正文或完整私人页面截图放入台账。

### 免费公测退出条件

不要只按日期结束免费期。至少达到以下条件后再进入收费试运行：

- 覆盖至少 3 个 Android 品牌和 3 个主要系统版本；
- 收到不少于 100 份可用真实反馈；
- 对高频目标应用形成明确的已支持、部分支持和暂不支持清单；
- 危险误触率达到预设红线以下，并单独公布口径；
- 无障碍自动关闭有清楚的厂商设置引导；
- 生产签名、隐私网址、反馈响应流程和账号删除流程准备完成。

## 第二阶段：可选的在线反馈接口

只有用户量让人工复制反馈明显失控时，才加入后台反馈接口。加入后必须更新隐私说明、申请网络权限，并在发送前取得明确同意。

允许上传的字段采用白名单：反馈编号、轻跳版本、设备品牌和型号、Android/API 版本、问题类型、用户填写的目标应用、用户描述、最后一条分类诊断、用户可选联系方式。禁止上传无障碍节点树、页面正文、控件全文、账号、密码、验证码、IMEI、通讯录、广告标识符和已安装应用完整清单。

接口需要 HTTPS、请求频率限制、内容长度限制、后台权限控制、审计记录和明确的数据保留期限。建议匿名反馈保留 90 天，形成兼容结论后删除原始文本；用户提供联系方式时，应允许其请求删除。

## 第三阶段：账号系统

账号系统应在支付前先以“可登录但仍免费”的方式灰度验证。登录与广告识别逻辑分离：正式账号版未登录、权益失效或用户退出登录时，应关闭总开关并让无障碍服务直接返回，不再扫描第三方应用；登录提示只显示在轻跳自己的首页。

建议最小数据模型：

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| users | id、status、created_at、deleted_at | 轻跳内部账号，不直接使用手机号作为主键 |
| identities | user_id、provider、provider_subject、verified_at | 邮箱、微信、华为或 Google 等登录身份 |
| devices | user_id、installation_id、model、last_seen_at、revoked_at | 控制设备数量和远程退出，不收集 IMEI |
| purchases | user_id、channel、product_id、order_id、encrypted_purchase_token、purchase_token_hash、state | 保存经服务端验证的订单；渠道令牌加密保存以便复核，哈希用于查重 |
| entitlements | user_id、type、starts_at、ends_at、source_purchase_id | `lifetime_pro` 的结束时间为空 |
| feedback | user_id 可空、report_id、category、payload、status | 允许公测匿名反馈以后绑定账号，但必须由用户主动操作 |

第一版登录建议支持邮箱验证码或可信渠道登录，避免自建密码存储。若主要用户来自中国大陆并坚持手机号验证码，需要承担短信成本、风控、号码更换和合规处理；9.9 永久收入很难覆盖长期短信和人工兼容成本。无论采用哪种方式，都要提供应用内退出登录、设备管理、账号注销，以及无需安装应用也能发起删除请求的网页入口。

## 第四阶段：9.9 永久权益

产品定义为一次性非消耗型永久权益：

- 商品 ID 示例：`qing_tiao_pro_lifetime`；
- 展示价格：人民币 9.9 元作为首发或早鸟价；
- 购买结果绑定轻跳账号，同时保存渠道订单；
- 换手机后登录同一账号可以恢复权益；
- 首期建议最多同时绑定 2 台设备，允许用户自助移除旧设备；
- 退款、撤销或渠道判定无效后，服务端同步撤销权益；
- 客户端缓存短期离线凭证，建议允许连续离线使用 7 天，之后重新验证；
- 客户端显示的“已购买”不能作为唯一依据，订单必须由服务端向支付渠道验证。

9.9 可以用作早期用户价格，但永久权益会带来长期适配和客服成本。建议限定为“前 500 名或首发 30 天 9.9”，同时在支付页面永久保存用户实际购买时的权益说明。后续标准价格可以根据真实维护成本调整，新价格不能影响已购买的永久权益。

## 免费用户与公测用户迁移

建议采用以下规则：

- 正式收费前至少提前 14 天公告；
- 公测用户首次登录后自动继承本机反馈编号，但只有用户主动确认才绑定历史反馈；
- 提交过可复现有效反馈的用户可以获得 9.9 早鸟价或兑换码；
- 正式收费后保留模拟测试、权限管理、安全保护、诊断导出和停止服务能力；
- 付费墙不能阻止用户关闭无障碍服务、导出自己的诊断或申请删除账号；
- 对暂未付费用户展示清楚的功能差异和价格，不制造虚假倒计时。

## 渠道支付

- Google Play 包：数字功能在应用内收费时使用 [Google Play Billing](https://support.google.com/googleplay/android-developer/answer/9858738)，并把购买令牌交给服务端验证。永久 Pro 使用[非消耗型一次性商品](https://developer.android.com/google/play/billing/one-time-products)。
- Huawei AppGallery 包：使用 [Huawei IAP](https://developer.huawei.com/consumer/en/hms/huawei-iap/) 并单独验证华为订单。
- 官网或直接分发包：可以使用独立支付渠道，但应与商店包隔离构建和配置，避免在受限制的商店包内引导到外部支付。

Google Play 中只要允许创建账号，就必须同时提供应用内删除入口和无需安装应用也能访问的网页删除入口；删除账号时要处理关联数据。实现账号功能时应把这项要求纳入验收，而不是上线后补做。参考 [Google Play 账号删除要求](https://support.google.com/googleplay/android-developer/answer/13327111)。

不同渠道最终都写入同一种 `lifetime_pro` 权益，客户端只读取统一权益状态，不直接根据“支付宝成功页面”或本地布尔值解锁。

## 小红书首轮推广执行

首轮只承诺可验证内容：Android、无需 Root、本地识别、用户选择应用、无法识别时保持原样。帖子包含 APK 官方 Release 链接、SHA-256、支持系统、权限用途、已知限制和反馈方式。

建议连续发布三类内容：

1. 同一台手机同一应用的真实冷启动录屏；
2. 为什么需要无障碍权限，以及轻跳不联网、不截图的说明；
3. 一周公测报告：收到多少有效反馈、修复哪些问题、哪些仍未解决。

每周公开“样本量、成功、漏跳、普通误触、危险误触、服务被系统关闭”的实际数量。兼容率分母必须是确实出现广告并完成观察的启动次数，不能把没有出现广告的启动算作成功。

# 轻跳产品化与变现路线

更新日期：2026-10-24

## 产品定位

轻跳的核心承诺是：**本地、克制、可解释地处理用户主动选择应用中的开屏广告按钮。**

推广时避免“所有手机、所有应用、100% 秒跳”等无法验证的承诺。更可靠的表述是“覆盖常见可读跳过按钮；无法识别时保持原样；用户可以看到最近诊断”。

## 同类项目中值得借鉴的产品思想

| 项目 | 值得借鉴 | 许可证或边界 | 轻跳的采用方式 |
| --- | --- | --- | --- |
| [GKD](https://github.com/gkd-kit/gkd) | 高级选择器、订阅规则、快照审查、按应用规则组 | GPL-3.0-only；仓库同时声明禁止商业用途 | 只借鉴“规则应可审查”的产品思想，不复制代码、选择器语法或规则库 |
| [SmartSkip](https://github.com/SZz-Gx/smartskip) | 多因素评分、硬性安全否决、点击前复核、点击后验证、最小化保存数据 | MIT | 独立实现锁屏/敏感页面否决、实时节点复核和分类诊断；后续再做可解释评分 |
| [Anti-ads](https://github.com/Watanabehato/Anti-ads) | 授权与实际连接分开显示、右上角几何保护、配置 revision、诊断测试靶、CI | MIT | 保留“系统授权”和“服务实际连接”两个状态；加入自动构建；后续增加几何与配置 revision |
| [NoShakingAD](https://github.com/WeiyePlayer/no-shakingAD) | 只在启动短窗口限制摇一摇、通知用户状态、按应用配置 | 仓库许可需单独确认 | 当前不引入 Shizuku 或传感器控制，避免扩大权限和售后复杂度 |

本版本没有复制上述项目的源代码。涉及商业化前，任何未来引入的第三方代码都必须逐项核对许可证、保留声明，并记录来源与修改。

## 推荐的收费模型

### 免费版必须保留

- 总开关、系统授权状态和服务连接状态；
- 选择应用；
- 常见开屏跳过规则；
- 误触保护、锁屏和敏感页面保护；
- 模拟测试和最近诊断；
- 完整的隐私披露与关闭方式。

安全、隐私和停止服务能力不能作为付费墙。

### 一次性 Pro 解锁

当前产品主要在本机工作，尚未持续提供云服务。优先采用一次性非消耗型购买，而不是订阅。Pro 可以包含：

- 每应用独立模式、识别窗口和点击上限；
- 自定义文字/资源 ID 规则；
- 规则导入、导出和本地备份；
- 更长的本机诊断历史和筛选；
- 规则测试器、控件结构检查器；
- 新功能抢先体验。

只有在持续提供经过审核的在线规则更新、跨设备同步或人工兼容支持后，才考虑订阅。Google Play 明确要求订阅必须持续提供重复价值；单次功能解锁应使用一次性产品。

### 渠道建议

- Google Play 版本：数字功能收费必须使用 [Google Play Billing](https://support.google.com/googleplay/android-developer/answer/9858738)；需要完成 [AccessibilityService 权限声明](https://support.google.com/googleplay/android-developer/answer/10964491)、应用内显著披露和演示视频。
- 华为 AppGallery 版本：单独接入 Huawei IAP，并单独维护渠道包；不要在 Play 包中混用外部数字商品支付。提交前按 [AppGallery Policy Center](https://developer.huawei.com/consumer/en/policy-center/) 的当期规则复核。
- GitHub 版本：作为公开测试渠道，保持核心功能可用，APK 明确标记测试签名和非商店审核版本。

## 版本路线

### 0.3：产品基础

- 可搜索且可靠保存的应用选择器；
- 点击前实时复核；
- 锁屏、系统敏感包、输入/密码/身份验证页面硬性否决；
- 隐私化诊断导出和分享入口；
- GitHub Actions 自动构建；
- 隐私政策和商店文案。

### 0.4：可解释与验证

- 候选按钮评分及逐项理由；
- 点击后 600 毫秒重新采样，区分“页面已变化”“按钮仍存在”“跳到外部应用”；
- 每个应用的成功、失败、误触反馈；
- 对抗性测试页覆盖伪跳过、支付页面、输入框和大面积广告素材。

### 0.5：Pro 基础

- 每应用独立设置；
- 自定义规则和本地规则包；
- 规则导入/导出；
- 购买权益接口抽象，分别实现 Play Billing 和 Huawei IAP。

### 1.0：商店发布

- 正式生产签名和密钥备份；
- Play/AppGallery 审核材料、隐私网址、数据安全表和功能演示视频；
- 至少覆盖 3 个系统品牌和多个 Android 版本的回归矩阵；
- 明确公布兼容样本数、跳过成功率、漏跳率和危险误触率。

## 推广内容支柱

1. **真实速度对比**：同一设备冷启动前后录屏，只展示可重复样本。
2. **本地隐私**：清单无网络权限，不保存页面正文，可公开审计源码。
3. **克制安全**：遇到输入、密码、身份验证和系统敏感界面立即停止。
4. **公开验证**：每个版本公开测试数量、已知限制、APK 哈希和签名方式。
5. **问题闭环**：用户通过匿名诊断反馈，按应用和广告 SDK 建立兼容清单。

首批渠道建议：GitHub Release、酷安开发者动态、Bilibili 实测视频、小红书/抖音短视频的真实冷启动对比。所有平台统一使用“测试版”“可读按钮”“无法识别时不操作”等准确措辞。

## 核心指标

- 首次授权完成率；
- 选择至少 1 个应用的用户比例；
- 模拟测试通过率；
- 每 100 次真实开屏的成功跳过、漏跳、普通误触和危险误触次数；
- 7 日仍保持服务可用的设备比例；
- 诊断反馈从提交到规则修复的中位时间；
- 免费到 Pro 的转化率及退款率。

危险误触必须单独统计，不能被总体成功率掩盖。
